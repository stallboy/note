# 杀戮尖塔 — 总览与核心循环

## 一、游戏概述

《杀戮尖塔》(Slay the Spire) 由 Mega Crit Games 开发，是 **DBG（牌组构建）+ Roguelike** 品类的开创者。玩家操控一个角色，通过回合制卡牌战斗攀登尖塔，在途中不断获取卡牌、遗物和资源，最终击败塔顶Boss。

**核心定位**：将传统卡牌游戏的构筑乐趣与Roguelike的单局不可逆性结合，创造"每局都不同"的体验深度。

## 二、核心循环

```
┌─────────────────────────────────────────────────────┐
│                    攀塔大循环                         │
│                                                     │
│  选择路径 → 进入房间(战斗/事件/商店/宝箱/休息)        │
│      ↓                                              │
│  获得奖励(卡牌/遗物/金币/药水)                        │
│      ↓                                              │
│  调整卡组(添加/移除/升级卡牌)                         │
│      ↓                                              │
│  面对更强的敌人 → 循环                                │
└─────────────────────────────────────────────────────┘
```

**核心循环的节奏设计**：

| 章节 | 楼层 | 定位 | 核心体验 |
|------|------|------|----------|
| Act 1 | 1-17 | 站稳脚跟 | 学习基础、建立初步流派方向 |
| Act 2 | 18-34 | 巩固流派 | 深化卡组、获取关键遗物 |
| Act 3 | 35-51 | 考验成型 | 卡组是否足以应对复杂战斗 |
| Act 4 | 52-54 | 终极挑战 | 对卡组完整性的极致检验 |

## 三、设计哲学

### 1. 限制即策略

杀戮尖塔最核心的设计理念是**通过限制创造深度**：

- **每回合仅3点能量**：迫使玩家在有限的资源内做出最优选择
- **每回合抽5张牌**：限制了信息量和操作空间
- **护甲不跨回合**：每回合都要重新决策"攻"还是"守"
- **手牌上限10张**：防止无限抽牌的失控

这些限制不是"简化"，而是将策略空间压缩到可认知的范围内。玩家不需要处理海量信息，但需要在有限选项中做出精确判断。

### 2. 透明化优于隐藏

杀戮尖塔将大量传统游戏中隐藏的信息公开：

- **敌人意图公开**：玩家可以清楚看到敌人下一步会做什么
- **地图全可见**：玩家可以提前规划路径
- **卡牌效果明确**：没有随机性描述（"有几率"），效果都是确定的

**为什么这么设计**：传统Roguelike的挫败感很大程度上来自"信息不足导致的意外死亡"。杀戮尖塔通过透明化将"运气"降到最低——当你死亡时，你能追溯到一个具体的决策错误，而非"运气不好"。这大大降低了挫败感，同时保留了Roguelike的核心张力。

### 3. 风险-收益无处不在

游戏的几乎每一个决策点都嵌入了两难选择：

| 决策场景 | 安全选择 | 风险选择 |
|----------|----------|----------|
| 路径规划 | 多休息点路线 | 多精英路线（更多遗物但更危险） |
| Boss遗物 | 不拿（无代价） | 拿（+1能量但有惩罚） |
| 事件 | 保守选项 | 高回报但有诅咒/HP代价 |
| 卡组构建 | 只拿确定有用的卡 | 尝试新流派组合 |
| 战斗出牌 | 出防御保命 | 贪伤害拼击杀 |

**为什么这么设计**：风险-收益的两难是策略游戏的灵魂。当每个决策都有"正确答案"时，游戏变成了执行最优解；只有当决策需要权衡时，才产生真正的策略深度和个人风格。

### 4. 系统深度来源于交互

杀戮尖塔没有任何单一系统是特别复杂的。游戏的深度来源于**多个简单系统之间的交互**：

```
卡牌 × 遗物 → 流派定义（如死灵之书 + 消耗流）
遗物 × 药水 → 紧急策略（如关键时刻使用药水配合遗物）
卡牌 × 状态/诅咒 → 转化策略（如Du-Vu Doll把诅咒变力量）
角色 × 所有系统 → 四种完全不同的游戏体验
```

### 5. 失败应有价值

- 失败时可以追溯决策错误，而非归咎于运气
- 进阶系统允许失败后仍解锁下一级（在第四幕失败也算）
- 单局时长约30-60分钟，失败不会导致过大的时间损失

## 四、系统架构总览

```
                        ┌──────────┐
                        │  进阶系统  │ ← 全局难度调节
                        └────┬─────┘
                             │
┌────────┐    ┌──────────┐   │   ┌──────────┐    ┌────────┐
│ 角色系统 │───→│  地图系统  │←──┘──→│  事件系统  │←───│ 诅咒系统│
└────────┘    └────┬─────┘       └──────────┘    └────────┘
                   │ 决定遇到什么        ↑
      ┌────────────┼────────────┐      │
      v            v            v      │
┌──────────┐ ┌──────────┐ ┌──────────┐ │
│ 战斗系统  │ │  商店系统  │ │  宝箱系统  │ │
└────┬─────┘ └──────────┘ └──────────┘ │
     │ 获得奖励                          │
     v                                  │
┌──────────┐    ┌──────────┐            │
│ 卡牌系统  │    │ 遗物系统  │────────────┘
└──────────┘    └──────────┘
     ↑                ↑
     └──── 药水系统 ────┘
```

**系统的层次关系**：

| 层次 | 系统 | 作用 |
|------|------|------|
| 元系统 | 进阶、角色 | 定义全局参数和体验框架 |
| 流程系统 | 地图、事件 | 定义游戏节奏和决策节点 |
| 奖励系统 | 战斗奖励、商店、宝箱 | 驱动卡组构建 |
| 核心玩法 | 卡牌、战斗 | 每时每刻的游戏体验 |
| 持久系统 | 遗物、药水 | 跨战斗的持续影响 |
| 惩罚系统 | 诅咒、状态牌 | 为其他系统的收益提供代价 |

## 五、设计启示

1. **少即是多**：单个系统保持简单，深度来自系统间的交互
2. **让玩家理解失败**：透明化设计让每次死亡都有教育价值
3. **约束创造创意**：3能量、5抽牌的限制正是策略深度的来源
4. **全局统一的代价语言**：HP、诅咒、金币、遗物——所有系统共享同一套"代价-收益"语言
5. **节奏控制**：保底设计（第9层必宝箱、第15层必休息）确保基本体验质量
